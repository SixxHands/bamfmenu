# early/core/json — a tiny, dependency-free JSON reader for descriptor files
## Intent
The service jar runs **pre-Minecraft** and ships no Gson, so per the self-contained-jar rule (Java + LWJGL only) this layer hand-rolls exactly the JSON support the descriptor files need — nothing more. Per the plan doc it landed in **** as the reader for the per-song manifest `song.json` (`songs/<id>/song.json`), and is deliberately reused unchanged for `panel.track` / `panel.json` in the later animation phases. It is read-only for now; the editor is the phase that would add writing. The design bias is **forward-compatibility**: unknown fields are ignored and a missing/wrong-typed field falls back to a caller-supplied default, so a malformed or partial descriptor never throws into the runtime — callers degrade to defaults instead.

## Components
- **`Json`** — the single `public final` class in this folder; pure logic, no GL and no Minecraft. A private constructor makes it a static utility. Public surface:
  - `static Object parse(String src)` — recursive-descent parse of a whole document into the canonical Java tree (`Map<String,Object>` | `List<Object>` | `String` | `Double` | `Boolean` | `null`); throws `JsonException` on malformed or trailing input. All JSON numbers are produced as `Double`.
  - `static Obj object(String src)` — parse-and-view convenience: returns an `Obj` over the top-level object, or an **empty `Obj`** if the source is not an object or fails to parse (the `JsonException` is swallowed), so callers read with defaults and no null checks.
  - `static final class JsonException extends RuntimeException` — thrown on malformed input; callers catch it and degrade.
  - `static final class Obj` — a read-only, **defaulting** view over a parsed `Map<String,Object>`. Every typed getter returns the default when the key is absent or holds the wrong type: `has`, `str(key,def)`, `dbl(key,def)`, `f(key,def)`, `i(key,def)`, `bool(key,def)`, `obj(key)` (nested object, or an empty `Obj` so chained reads never NPE), and `keys()` (insertion-ordered key set, e.g. to iterate a `charts` map's difficulty names).
  - `private static final class Parser` — the recursive-descent state machine (`value`/`object`/`array`/`string`/`number`/`bool`, plus `ws`/`peek`/`expect`/`lit` helpers). Covers objects, arrays, strings with the standard escapes and `\uXXXX`, numbers (int/double via `Double.parseDouble`), and `true`/`false`/`null`. Not exposed.

## How it works
A caller hands raw descriptor text to `Json.object(src)`. Internally that runs `parse`, which drives a fresh `Parser` over the string: `ws()` skips whitespace, `value()` dispatches on the first significant char into `object()` / `array()` / `string()` / `bool()` / `null` / `number()`, and after the top-level value any trailing non-whitespace is rejected as `JsonException`. The resulting tree is wrapped in an `Obj`, and downstream loaders pull typed fields with defaults (e.g. the song loader reads `name`, `label`, `order`, `ogg`, `bpm`, and the optional `detector` block off the `Obj`). Because every getter and the `object(...)` entry point fall back to defaults / an empty `Obj` rather than throwing, a song that omits or mistypes a field simply gets the default — the read-only, defaulting view is the whole forward-compatibility contract.

## Boundaries
- **Depends on:** only the JDK (`java.util` collections — `ArrayList`, `LinkedHashMap`, `List`, `Map`). No GL, no Minecraft, no third-party JSON library — it satisfies the self-contained-jar rule by itself.
- **Depended on by:** the `early/core` descriptor loaders — notably the song registry/loader that parses `songs/<id>/song.json`, and (later, by design) the `panel.track` / `panel.json` readers.
- **Invariants:** lives under `core/`, so it never imports `bios/` (the GL/host layer) and is editor-reusable headless logic. It is thread-agnostic stateless utility code (the per-parse `Parser` holds all mutable state on the stack of one call); parsing produces an immutable-shaped tree and the `Obj` view is read-only.
