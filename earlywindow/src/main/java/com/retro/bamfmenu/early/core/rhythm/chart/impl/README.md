# early/core/rhythm/chart/impl — the concrete `Charter` builders + the auto-charting DSP that turns a song into notes
## Intent
This is the implementation side of the **Charter seam**: the parent `chart/` package declares the `Charter` interface, and this folder holds the concrete builders plus the immutable `ChartRequest` carrier they consume. The seam exists so the head ("the game is *fed* a chart") never inlines the generate chain — `RhythmScreen.onEnter` shrinks to `charter.build(ChartRequest.fromAudio(...))`, and the runtime chart source is removable/swappable in one place. `DspCharter` is today's verbatim runtime chain (moved out of `RhythmScreen.onEnter` unchanged); `FileCharter` is the Phase-4 endpoint where the game reads a committed `.chart` instead of analysing audio at play; `ChartGenerator` is the pure DSP-to-notes auto-charter both the runtime and the editor's "Generate" reuse. Pure logic only — no GL, no Minecraft, headless and editor-reusable, consistent with the `core/` half of `early/`.

## Components
- **`ChartRequest`** — immutable inputs handed to a `Charter` so the head passes a *request* instead of inlining the chain. Fields: `audio` (decoded song = the DSP analysis source; null for a file-backed build), `det` (the difficulty's tuned `DetectorConfig`), `lanes`, `bpm` (grid tempo hint; 0 = auto), `chartPath` (Phase-4 committed-chart path; null today, reserved so the unhook is a one-place swap). Accessors `audio()`/`det()`/`lanes()`/`bpm()`/`chartPath()`; factory `fromAudio(audio, det, lanes, bpm)` for the runtime path. Forward-compat by design: `FileCharter` ignores `audio`, `DspCharter` ignores `chartPath`.
- **`DspCharter` implements `Charter`** — the runtime chart source. `build(ChartRequest)` runs the exact cascade that used to live in `RhythmScreen.onEnter`: `ChartGenerator.generateMelodic(...)` (Phase-3 piano-priority) → `generateV2(...)` (Phase-1 whole-mix SuperFlux) → `generate(...)` (legacy onset/ZCR) → `RhythmEngine.demoChart()`, each tried only if the prior returned empty, so a failed analysis (e.g. decode failure) never leaves an empty highway. Returns `List<RhythmEngine.Note>`. swaps this impl for `FileCharter`; `DspCharter` survives as the editor's "Generate".
- **`FileCharter` implements `Charter`** — the Phase-4 runtime charter that is fed a committed chart. `build(ChartRequest)` reads the bundled resource named by `req.chartPath()`, parses it via `ChartIO.read(text, "normal")`, and returns its notes; the audio is ignored (it still plays, no analysis drives the chart). Any failure path (null/blank path, missing file, parse error) returns `List.of()` = "uncharted", so the caller marks the song/difficulty unplayable rather than starting an empty highway. Static helpers `chartPath(songId, diff)` → `/songs/<id>/<token>.chart` and `hasChart(songId, diff)` are the jukebox's source of truth for which difficulties exist; existence is memoized in the `EXISTS` `ConcurrentHashMap` because it is polled per-frame while the difficulty menu is open. Classpath-only today.
- **`ChartGenerator`** — the pure auto-charter; static utility (private ctor), arrays in / notes out, no GL or audio handles. Three public generators, newest first: `generateMelodic(...)`; `generateV2(...)`; `generate(...)` (legacy RMS-flux peak-pick with zero-crossing-rate lanes). `sensitivity` (0..1) is the shared difficulty knob (higher = denser). Private helpers `laneFromCentroid`, `laneFor`, `addPercussionFill`. All variants emit taps only (`hold = 0`); holds/beat-snap refinements are later phases.

## How it works
The head builds a `ChartRequest` (today via `ChartRequest.fromAudio(p, det, LANES, bpm)`) and calls `Charter.build(req)`. The bound impl decides where notes come from:

- `DspCharter` pulls precomputed DSP features off the `AudioPlayer` (`melodicOdf()`, `melodicPitch()`, `melodicF0()`, `percussionOdf()`, `cdConf()`, `superflux()`, `centroid()`, `onsets()`, `zcr()`, frame/hop timings) and feeds them to the `ChartGenerator` cascade with the difficulty's `DetectorConfig` knobs, falling back down the chain until something non-empty (or the demo chart) is produced.
- `FileCharter` ignores the audio entirely, reads the committed `.chart` resource at `req.chartPath()`, and parses it via `ChartIO`.

Either way `build` returns `List<RhythmEngine.Note>`, which the engine consumes as the playable highway. `ChartRequest` is the stable contract that lets the runtime swap from DSP-charting to file-charting without changing a single call site.

## Boundaries
Depends on sibling `core/` packages only: `core.rhythm.chart` (`Charter`, `Chart`, `ChartIO`), `core.rhythm.RhythmEngine` (the `Note` type + `demoChart()`), `core.audio.AudioPlayer` (feature source), `core.tuning.DetectorConfig`, `core.dsp` (`BeatGrid`, `OnsetPicker`), and `core.song.Difficulty`. Consumed by the rhythm head (the `bios/` screen layer holds a `Charter` and calls `build`); the jukebox/difficulty menu calls `FileCharter.hasChart`/`chartPath`. Invariants: this is `core/` — it **never imports `bios/`** and touches no GL or Minecraft; `ChartGenerator` is a pure function (no mutable shared state) and `FileCharter.EXISTS` is a `ConcurrentHashMap` so per-frame existence polling is safe regardless of caller thread.
